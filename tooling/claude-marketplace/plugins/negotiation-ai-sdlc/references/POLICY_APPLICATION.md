# Policy Application Contract

1. Discover policies from the canonical policy root and existing project governance documents.
2. Read frontmatter before using a policy.
3. Apply a policy as mandatory only when `status: approved` and scope covers the change.
4. Treat `draft`, missing owner, expired review date, contradictory requirements, or unclear scope as an explicit gap.
5. Map applicable controls to requirement, acceptance-criterion, plan-step, test, and evidence IDs.
6. Do not claim legal, regulatory, security, privacy, or accessibility compliance solely from code inspection or a template.
7. An exception requires control, scope, rationale, compensating control, owner, approval, expiry, and re-review trigger.
8. Policy assessors are read-only. They report findings and do not silently alter artifacts or implementation.
